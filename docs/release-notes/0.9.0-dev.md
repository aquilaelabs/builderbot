# BuilderBot 0.9.0, dev build (@TAG@)

A pre-release on the dev channel: the whole of 0.9.0 as it stands. It is never the latest release, and a container on `:latest` does not move to it; an install on the dev channel (Controller settings, Updates) is offered it.

**BuilderBot OS is the experimental edition.** It is the first build of the appliance image published, and the edition most likely to break: install it on a machine or a VM you can wipe. Everybody else: the container edition is the one to run.

## What is in this release

- The controller's container image, `ghcr.io/@REPO@:@TAG@`
- The bare-metal bundle, `builderbot-controller-*.tar.gz`, with its sha256 and build attestation
- BuilderBot OS: the raw disk, the ISO installer, the USB stick image, qcow2 and OVA, each with its sha256
- The Android app and the Windows companion, attached by their own builds a few minutes after the release

## What is new

- **BuilderBot OS**, the appliance image: a read-only root in two slots, updates from the page that boot on trial and fall back by themselves, and BuilderBot's mark on the console at every boot.
- **A NAS on the controller's own machine**: the first run sets up its disks (how many may fail, the layout picked from the disks), ZFS pools, a mixed-disk array with parity, encrypted pools, snapshots, shares over SMB and NFS given to people and roles, backups, disk health on the bell, a UPS, reporting.
- **One Library**: toolchains, coding agents, tool packs and apps on one page from the vetted catalog's signed index, Installed and Updates filters, a page of its own for every entry and every installed thing, and a pack's or app's own icon.
- **Any coding agent from the catalog**, and any model through a node's model router (LiteLLM), with OpenCode as Any model.
- **An agent on your git host**: `bb forge` works pull requests, issues, CI runs and their logs, and releases on GitHub, GitLab, Gitea and Forgejo with the project's token, which never reaches a session; each project's Permissions view says what the token allows and lets you turn any of it off.
- **Every page in one order**: the page's head, its numbers, then its search and buttons, then the list, the same on a phone and at a desk.
- **System containers on the Containers page**: nginx, the scanners and the model router pinned at the top in rows like any other container, each with Configure to its own page.
- The dev channel itself, the bell reaching you by mail, ntfy and the rest, one token per git host and account, key stores opened less at a time, sign-ins bound to their browser, VMs and USB devices on the controller's machine, Let's Encrypt on the nginx page, and polish across every page.

The full list is the Unreleased section of [CHANGELOG.md](https://github.com/@REPO@/blob/@TAG@/CHANGELOG.md).
